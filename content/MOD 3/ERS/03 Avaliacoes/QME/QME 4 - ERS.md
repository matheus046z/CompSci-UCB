# 1

> [!question] Exercício 1
> A engenharia de software ágil combina uma filosofia com um conjunto de princípios de desenvolvimento. A filosofia defende a satisfação do cliente e a entrega incremental antecipada; equipes de projeto pequenas e altamente motivadas; métodos informais; artefatos de engenharia de software mínimos; e, acima de tudo, simplicidade no desenvolvimento geral. Acerca desse tema, é **INCORRETO** afirmar:
>
> **A.** Uma equipe ágil é aquela capaz de controlar de modo adequado as mudanças. Mas, como a mudança tem um custo associado, existe na abordagem ágil uma grande resistência à aceitação das alterações solicitadas pelo cliente.
>
> **B.** Uma equipe ágil reconhece que o software é desenvolvido por indivíduos trabalhando em equipes e que as habilidades dessas pessoas e suas capacidades de colaborar estão no cerne do sucesso do projeto.
>
> **C.** Desenvolvimento ágil não significa que nenhum documento é criado; significa que apenas os documentos que serão consultados mais adiante no processo de desenvolvimento são criados.
>
> **D.** Em intervalos regulares, a equipe reflete sobre como se tornar mais eficaz e, então, refina e ajusta seu comportamento de acordo.
>
> **E.** Um processo ágil reduz o custo das alterações porque o software é entregue de forma incremental e as alterações podem ser mais bem controladas dentro dos incrementos.
>
>> [!question]- Resposta
>>
>> **Alternativa incorreta: A.**
>>
>> **A. Incorreta.** As abordagens ágeis não apresentam grande resistência às mudanças solicitadas pelo cliente. Pelo contrário, aceitam alterações nos requisitos, inclusive em fases avançadas, procurando incorporá-las de maneira controlada e com geração de valor.
>>
>> **B. Correta.** O desenvolvimento ágil valoriza indivíduos, interações, colaboração e equipes capacitadas e motivadas, reconhecendo que esses fatores são essenciais para o sucesso do projeto.
>>
>> **C. Correta.** Agilidade não significa ausência de documentação. A proposta é produzir documentação útil e suficiente, evitando documentos excessivos que não serão utilizados na continuidade do projeto.
>>
>> **D. Correta.** A afirmação corresponde a um dos princípios do Manifesto Ágil: a equipe deve avaliar regularmente sua forma de trabalhar e ajustar seu comportamento para aumentar a eficácia.
>>
>> **E. Correta.** A entrega incremental permite incorporar mudanças em partes menores do sistema, diminuindo riscos e tornando os impactos e custos das alterações mais fáceis de controlar.

# 2

> [!question] Exercício 2
> A respeito do Scrum e da Extreme Programming (XP), assinale a alternativa **INCORRETA**:
>
> **A.** Na XP, os programadores desenvolvem o software criando primeiro os testes e, depois, as funcionalidades.
>
> **B.** Tanto no Scrum quanto na XP, nenhuma documentação é produzida, porque o importante é a entrega do software funcionando.
>
> **C.** No Scrum, uma parte dos requisitos é selecionada para implementação em um esforço de desenvolvimento conhecido como *sprint*.
>
> **D.** Na XP, a implementação do código é feita em dupla, ou seja, dois desenvolvedores trabalham juntos em um mesmo computador.
>
> **E.** No Scrum, os requisitos correspondentes àquilo que deve ser implementado no sistema são organizados no que é conhecido como *Product Backlog*.
>
>> [!question]- Resposta
>>
>> **Alternativa incorreta: B.**
>>
>> **A. Correta.** A XP adota o desenvolvimento orientado a testes, conhecido como TDD (*Test-Driven Development*), no qual os testes são escritos antes do código necessário para implementar a funcionalidade.
>>
>> **B. Incorreta.** Scrum e XP não proíbem a produção de documentação. Os métodos ágeis valorizam mais o software funcionando do que uma documentação abrangente, mas produzem os documentos necessários e úteis ao projeto.
>>
>> **C. Correta.** No Scrum, itens do *Product Backlog* são selecionados para desenvolvimento durante uma *sprint*, que é um período de trabalho com duração definida.
>>
>> **D. Correta.** A programação em pares é uma prática característica da XP. Dois desenvolvedores trabalham juntos: um escreve o código, enquanto o outro revisa e analisa continuamente o trabalho.
>>
>> **E. Correta.** O *Product Backlog* é a lista ordenada de funcionalidades, requisitos, melhorias e correções necessárias ao produto.


# 3

> [!question] Exercício 3
> Sobre o Modelo Incremental, é **INCORRETO** afirmar que:
>
> **A.** O modelo não responde bem à incorporação ou mudança de requisitos.
>
> **B.** Cada iteração passa pelas fases de levantamento de requisitos, análise, projeto e implementação.
>
> **C.** O sistema é dividido em partes, que são desenvolvidas de forma paralela e independente.
>
> **D.** É uma abordagem bastante utilizada pelas empresas para o desenvolvimento de software.
>
> **E.** Pode ser entendido como um modelo cascata sendo executado “diversas vezes”.
>
>> [!question]- Resposta
>>
>> **Alternativa incorreta: A.**
>>
>> **A. Incorreta.** O Modelo Incremental responde relativamente bem à incorporação e à mudança de requisitos. Como o sistema é construído em incrementos, alterações podem ser analisadas e incorporadas aos ciclos seguintes.
>>
>> **B. Correta.** Cada incremento percorre atividades típicas do desenvolvimento, como levantamento de requisitos, análise, projeto, implementação e testes.
>>
>> **C. Correta.** O sistema é dividido em partes ou incrementos, que podem ser desenvolvidos com certo grau de independência e, conforme a organização do projeto, de maneira paralela. Ao final, os incrementos são integrados para formar o sistema completo.
>>
>> **D. Correta.** O modelo é amplamente utilizado porque permite entregar funcionalidades gradualmente, obter retorno dos usuários e reduzir os riscos do desenvolvimento.
>>
>> **E. Correta.** De maneira simplificada, cada incremento pode ser visto como uma pequena execução do modelo em cascata, pois percorre sucessivamente as principais etapas do desenvolvimento. Esse ciclo é repetido para cada nova parte do sistema.

# 4

> [!question] Exercício 4
> Acerca das atividades envolvidas no processo de desenvolvimento de software, é **INCORRETO** dizer que:
>
> **A.** A atividade de análise tem como objetivo a transformação dos requisitos em uma visão mais sistêmica. Isso é feito por meio de um maior detalhamento dos requisitos elencados na fase de levantamento de requisitos.
>
> **B.** A atividade de levantamento de requisitos corresponde à etapa de compreensão do problema aplicada ao desenvolvimento de software.
>
> **C.** A especificação dos requisitos de um sistema não deve ter como foco “o que” deve ser feito, e sim “como” deve ser feito.
>
> **D.** A atividade de projeto tem como objetivo definir uma estrutura implementável para um produto de software que atenda aos requisitos especificados para ele. Nessa etapa, os requisitos são representados na forma de diagramas.
>
> **E.** A atividade de testes corresponde à etapa de validação e verificação das funcionalidades implementadas.
>
>> [!question]- Resposta
>>
>> **Alternativa incorreta: C.**
>>
>> **A. Correta.** Na análise, os requisitos levantados são detalhados e organizados para proporcionar uma visão mais completa e sistêmica do software e do problema que ele deverá solucionar.
>>
>> **B. Correta.** O levantamento de requisitos procura compreender o problema, as necessidades dos usuários, as regras de negócio e as funcionalidades esperadas para o sistema.
>>
>> **C. Incorreta.** A especificação de requisitos deve concentrar-se principalmente em **“o que”** o sistema deverá fazer, e não em **“como”** isso será implementado. As decisões sobre a forma de implementação pertencem principalmente às atividades de projeto e construção.
>>
>> **D. Correta.** A atividade de projeto transforma os requisitos em uma estrutura que possa ser implementada. Para isso, podem ser utilizados diagramas que representam elementos como arquitetura, componentes, classes e interações do sistema.
>>
>> **E. Correta.** Os testes verificam se o software foi construído corretamente e validam se as funcionalidades implementadas atendem às necessidades e aos requisitos definidos.


# 5

> [!question] Exercício 5
> A Engenharia de Software surgiu no contexto da crise do software, como uma alternativa para estruturar diferentes técnicas e metodologias destinadas ao desenvolvimento de software. Tendo como base esse contexto histórico, assinale o item **CORRETO** acerca do desenvolvimento de software naquela época:
>
> **A.** Não havia uma abordagem disciplinada para o desenvolvimento do software.
>
> **B.** A documentação era completa, suficiente e estava em conformidade com o software.
>
> **C.** Os projetos terminavam de acordo com os valores inicialmente previstos para o desenvolvimento do software.
>
> **D.** Os códigos eram de boa qualidade e de fácil manutenção.
>
> **E.** Os prazos inicialmente estabelecidos para o desenvolvimento do software eram cumpridos.
>
>> [!question]- Resposta
>>
>> **Alternativa correta: A.**
>>
>> **A. Correta.** Durante a crise do software, ainda não existia uma abordagem suficientemente sistemática e disciplinada para conduzir o desenvolvimento de sistemas cada vez maiores e mais complexos. Essa situação contribuiu para o surgimento da Engenharia de Software.
>>
>> **B. Incorreta.** A documentação frequentemente era insuficiente, desatualizada ou incompatível com o sistema efetivamente desenvolvido, dificultando sua compreensão e manutenção.
>>
>> **C. Incorreta.** Muitos projetos ultrapassavam os orçamentos inicialmente estabelecidos em razão de estimativas inadequadas, mudanças de requisitos e dificuldades no gerenciamento da complexidade.
>>
>> **D. Incorreta.** Era comum a produção de códigos com baixa qualidade, pouca estruturação e difícil manutenção, o que elevava os custos de correção e evolução dos sistemas.
>>
>> **E. Incorreta.** Os atrasos eram um dos principais sintomas da crise do software. Frequentemente, os projetos não eram concluídos dentro dos prazos inicialmente previstos.


# 6

> [!question] Exercício 6
> As metodologias de desenvolvimento de software têm como base um modelo de ciclo de vida, como o modelo cascata e o modelo espiral. Acerca desse tema, é **INCORRETO** afirmar que:
>
> **A.** Metodologias que seguem o modelo cascata possuem fases bem definidas e executadas em sequência.
>
> **B.** Em metodologias que seguem o modelo em espiral, o software é desenvolvido em uma ou mais iterações.
>
> **C.** Metodologias que seguem o modelo em espiral normalmente possuem um menor potencial de risco, uma vez que esse modelo lida explicitamente com a análise de riscos.
>
> **D.** Em metodologias que seguem o modelo cascata, não há sobreposição entre as fases, isto é, a fase seguinte **somente** pode ser executada após a finalização da fase anterior.
>
> **E.** Metodologias que seguem o modelo cascata possuem fases bem definidas, que podem ser desenvolvidas incrementalmente, em diferentes ciclos de desenvolvimento. Isto é, a fase seguinte **pode** ser executada, ainda que a fase anterior **não** tenha sido completamente finalizada.
>
>> [!question]- Resposta
>>
>> **Alternativa incorreta: E.**
>>
>> **A. Correta.** No modelo cascata, as atividades de desenvolvimento são organizadas em fases bem definidas, normalmente executadas em uma sequência previamente estabelecida.
>>
>> **B. Correta.** O modelo espiral é iterativo. O projeto percorre sucessivos ciclos ou voltas da espiral, e cada iteração pode produzir uma versão mais completa do software.
>>
>> **C. Correta.** A análise de riscos é uma característica central do modelo espiral. Em cada ciclo, os riscos são identificados, avaliados e tratados antes do avanço do projeto, reduzindo a possibilidade de problemas graves.
>>
>> **D. Correta.** No modelo cascata clássico, uma fase deve ser concluída antes do início da seguinte, sem sobreposição significativa entre elas. Essa rigidez dificulta o retorno a etapas anteriores.
>>
>> **E. Incorreta.** O desenvolvimento incremental em diferentes ciclos e a possibilidade de sobreposição entre fases não caracterizam o modelo cascata clássico. Nesse modelo, as fases são predominantemente sequenciais, e a etapa seguinte começa após a conclusão da anterior.

# 7

> [!question] Exercício 7
> Segundo Pressman, a Engenharia de Software consiste na aplicação de uma abordagem sistemática, disciplinada e quantificável ao desenvolvimento, à operação e à manutenção de software. Assim, podemos dizer que a Engenharia de Software tem como objetivo promover uma forma racional e planejada de desenvolver software. Tendo como base os estudos sobre Engenharia de Software, assinale a afirmação **INCORRETA**:
>
> **A.** A Engenharia de Software consiste em um esforço temporário empreendido para criar um produto, serviço ou resultado único.
>
> **B.** A preocupação com o software e com a maneira como ele é desenvolvido tem levado à adoção da prática da Engenharia de Software.
>
> **C.** A Engenharia de Software consiste na aplicação de princípios de engenharia ao desenvolvimento de software.
>
> **D.** A Engenharia de Software tem como foco a qualidade do software e, para seu desenvolvimento, sugere a adoção de um processo de desenvolvimento de software.
>
> **E.** A Engenharia de Software surgiu como uma resposta ao desenvolvimento caótico e desordenado de software e consiste na aplicação de metodologias e técnicas ao processo de criação de software.
>
>> [!question]- Resposta
>>
>> **Alternativa incorreta: A.**
>>
>> **A. Incorreta.** A definição apresentada corresponde ao conceito de **projeto**, e não ao de Engenharia de Software. Um projeto é um esforço temporário realizado para criar um produto, serviço ou resultado único.
>>
>> **B. Correta.** A crescente complexidade dos sistemas e a preocupação com a qualidade e a organização do desenvolvimento motivaram a adoção das práticas da Engenharia de Software.
>>
>> **C. Correta.** A Engenharia de Software aplica princípios, métodos e práticas de engenharia para desenvolver, operar, manter e evoluir sistemas de software.
>>
>> **D. Correta.** A qualidade é uma preocupação central da Engenharia de Software. A adoção de um processo estruturado ajuda a organizar as atividades e a produzir sistemas que atendam aos requisitos definidos.
>>
>> **E. Correta.** A Engenharia de Software surgiu como resposta à crise do software, marcada por atrasos, custos excessivos, baixa qualidade e dificuldades de manutenção. Para enfrentar esses problemas, utiliza processos, métodos, técnicas e ferramentas.


# 8

> [!question] Exercício 8
> Sobre o modelo Cascata, é **INCORRETO** afirmar que:
>
> **A.** O modelo prevê atividades muito bem definidas.
>
> **B.** O cliente somente visualizará o software no final do processo.
>
> **C.** Ele não prevê a “volta” para uma atividade anterior.
>
> **D.** É um modelo que requer que **todos** os requisitos do sistema sejam definidos no início do projeto.
>
> **E.** Mudanças de requisitos são bem recebidas nesse modelo.
>
>> [!question]- Resposta
>>
>> **Alternativa incorreta: E.**
>>
>> **A. Correta.** O modelo Cascata organiza o desenvolvimento em fases bem definidas, como requisitos, análise, projeto, implementação, testes e manutenção.
>>
>> **B. Correta.** Em sua forma clássica, o software funcional é apresentado ao cliente somente nas etapas finais. Isso limita a obtenção antecipada de retorno sobre o produto.
>>
>> **C. Correta.** O modelo Cascata clássico segue uma progressão sequencial e não prevê facilmente o retorno às etapas anteriores depois que elas foram concluídas.
>>
>> **D. Correta.** O modelo pressupõe que os requisitos sejam conhecidos, definidos e documentados no início do projeto, antes do avanço para as fases seguintes.
>>
>> **E. Incorreta.** Mudanças de requisitos não são bem recebidas pelo modelo Cascata, especialmente quando ocorrem em fases avançadas. Como as etapas são sequenciais, uma alteração pode exigir a revisão de documentos, projetos e componentes já concluídos, elevando custos e prazos.


# 9

> [!question] Exercício 9
> Sobre requisitos, é **INCORRETO** afirmar que:
>
> **A.** Requisitos Funcionais (RF) estão associados às funcionalidades providas pelo sistema.
>
> **B.** A escolha do banco de dados que será usado pelo sistema corresponde a um Requisito Funcional (RF).
>
> **C.** Requisitos Não Funcionais (RNF) estão associados a propriedades e restrições do sistema.
>
> **D.** Requisitos de segurança do sistema correspondem a Requisitos Não Funcionais (RNF).
>
> **E.** A especificação das ações de um cadastro de usuários corresponde a Requisitos Funcionais (RF).
>
>> [!question]- Resposta
>>
>> **Alternativa incorreta: B.**
>>
>> **A. Correta.** Os Requisitos Funcionais descrevem os serviços, comportamentos e funcionalidades que o sistema deve oferecer aos usuários ou a outros sistemas.
>>
>> **B. Incorreta.** A escolha de um banco de dados não descreve uma funcionalidade oferecida pelo sistema. Ela representa uma restrição tecnológica ou uma decisão de projeto e, dependendo do contexto, pode ser classificada como Requisito Não Funcional.
>>
>> **C. Correta.** Os Requisitos Não Funcionais definem propriedades de qualidade, condições e restrições relacionadas ao funcionamento ou ao desenvolvimento do sistema.
>>
>> **D. Correta.** Segurança é normalmente tratada como um Requisito Não Funcional, pois estabelece propriedades e restrições como autenticação, autorização, confidencialidade e proteção dos dados.
>>
>> **E. Correta.** Ações como cadastrar, consultar, alterar e excluir usuários descrevem serviços que o sistema deve executar e, portanto, correspondem a Requisitos Funcionais.

# 10

> [!question] Exercício 10
> Qual dos itens relacionados abaixo está de acordo com a filosofia do Movimento Ágil?
>
> **A.** Equipes de projeto cujas decisões são exclusivamente tomadas por um gerente de projetos.
>
> **B.** Priorizar mais o esforço em análise e projeto — e sua respectiva documentação — do que na entrega do software.
>
> **C.** Foco no processo.
>
> **D.** Responder a mudanças mais que seguir um plano.
>
> **E.** Equipes de projeto desmotivadas.
>
>> [!question]- Resposta
>>
>> **Alternativa correta: D.**
>>
>> **A. Incorreta.** O Movimento Ágil valoriza equipes colaborativas e auto-organizadas. As decisões não devem ficar exclusivamente concentradas no gerente de projetos.
>>
>> **B. Incorreta.** A filosofia ágil valoriza mais o software funcionando do que uma documentação abrangente. Análise, projeto e documentação continuam importantes, mas devem contribuir efetivamente para a entrega de valor.
>>
>> **C. Incorreta.** O Manifesto Ágil valoriza mais os **indivíduos e suas interações** do que os processos e as ferramentas. Isso não significa abandonar os processos, mas evitar que eles sejam priorizados em detrimento das pessoas.
>>
>> **D. Correta.** “Responder a mudanças mais que seguir um plano” é um dos quatro valores fundamentais do Manifesto Ágil. O planejamento continua importante, mas deve ser adaptável às mudanças e às necessidades do cliente.
>>
>> **E. Incorreta.** Os princípios ágeis defendem que os projetos sejam desenvolvidos por pessoas motivadas, às quais devem ser proporcionados o ambiente, o apoio e a confiança necessários.
